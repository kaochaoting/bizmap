# QuickNotifys PRD v1

## 1. 產品定位
QuickNotifys 是一個面向中小企業與店家的 **Google 商家檔案評論自動化產品**，核心任務是讓店家在收到新評論後，能更即時地被通知、更有條理地處理回覆，並將評論互動轉化為可追蹤的口碑管理流程。

## 2. 產品目標
QuickNotifys 要解決的不是單純「收到通知」而已，而是評論管理流程長期鬆散、回覆慢、沒有追蹤、無法沉澱成服務品質改善依據的問題。

### 核心目標
1. 新評論發生後，店家可在短時間內收到通知
2. 店家可有一致的評論處理流程
3. 店家可追蹤哪些評論已處理、未處理、待回覆
4. 評論互動可與 Kairos 生態圈其他節點形成串連

## 3. 核心問題
目前多數店家在評論管理上常見問題包括：
- 新評論出現時未即時發現
- 留言拖延回覆，影響信任感
- 負評沒有被優先處理
- 沒有一套後台知道評論目前處理到哪裡
- 評論互動沒有成為後續行銷、健檢或服務改善依據

### 問題陳述
**如何建立一套低門檻、即時、可追蹤的商家評論通知與回覆管理系統，讓店家能把評論從被動查看，提升為主動經營？**

## 4. 目標使用者

### 主要使用者
| 類型 | 特徵 | 核心需求 |
|---|---|---|
| 在地店家 | 高度依賴 Google 商家檔案 | 即時掌握評論、快速回覆 |
| 中小企業主 | 沒有專責客服或行銷人員 | 簡單通知、清楚流程 |
| 店務管理者 | 要控管多則評論處理狀態 | 後台追蹤與分工 |
| 行銷代管方 | 代客戶經營商家檔案 | 可複製、可管理的回覆流程 |

### 次要使用者
| 類型 | 任務 |
|---|---|
| Kairos 內部顧問 | 透過評論現況判斷客戶是否需要導入其他模組 |
| 品牌經營者 | 透過評論資料觀察顧客反饋與口碑變化 |

## 5. 生態圈定位
QuickNotifys 是 Kairos Engine 生態圈中的 **口碑互動與評論管理節點**。

### 與其他模組的關係
| 模組 | 關係 |
|---|---|
| Kairos.Site | 導流回商家主頁，補強品牌資訊與聯絡入口 |
| BizMap | 名錄曝光後若有評論互動需求，可導入 QuickNotifys |
| K-Core | 健檢時可判斷客戶是否缺評論處理流程，導入 QuickNotifys |
| MyCal | 評論互動後若需承接預約，可導向 MyCal |
| 秒傳名片 | 可作為快速分享聯絡與品牌入口 |

### 生態圈任務
- 補足商家與顧客互動後段管理
- 讓評論不只是被看見，而是被處理與被追蹤
- 形成「曝光 → 評論 → 回覆 → 信任 → 再轉換」的口碑循環

## 6. 核心功能範圍

### 6.1 MVP 功能
| 模組 | 功能 | 說明 |
|---|---|---|
| 商家綁定 | 綁定店家資料 | 建立店家與通知對象的基本設定 |
| 新評論通知 | 即時通知 | 收到新評論後，透過 LINE 或指定通知方式發送提醒 |
| 評論列表 | 評論紀錄查看 | 顯示評論內容、星等、時間、狀態 |
| 狀態追蹤 | 處理流程管理 | 已讀、待回覆、已回覆、忽略 |
| 回覆建議 | 協助產出回覆方向 | 提供人工可調整的回覆草稿或流程建議 |
| 基本後台 | 評論管理頁 | 查看評論、篩選狀態、更新處理狀態 |
| 基本導流 | 導向 Kairos.Site / MyCal / K-Core | 將評論管理延伸到其他節點 |

### 6.2 第二階段功能
| 模組 | 功能 | 說明 |
|---|---|---|
| 多店管理 | 管理多個商家據點 | 適合代管方或連鎖品牌 |
| 回覆模板 | 建立常用模板 | 提升回覆效率 |
| 負評優先提醒 | 風險評論優先處理 | 依星等或關鍵字標記 |
| 內部分工 | 指派處理人員 | 提升團隊運作效率 |
| 成效儀表板 | 評論處理數據 | 追蹤回覆率、平均處理時間 |

### 6.3 非本期範圍
- 完整客服系統
- 完整 CRM 替代方案
- 全自動無人工審核發送評論回覆
- 複雜社群訊息整合平台

## 7. 使用情境

### 情境一：新評論即時提醒
店家收到新評論後，QuickNotifys 自動發送 LINE 通知給店主或管理者，避免漏看。

### 情境二：負評優先處理
若收到低星評論，系統將其標為高優先級，提醒盡快處理。

### 情境三：店務分工
管理者可將評論標記為待回覆，後續由指定人員處理。

### 情境四：顧問健檢補強
K-Core 在健檢客戶時，若發現評論未被管理，可將 QuickNotifys 列為補強建議。

## 8. 使用者流程

```text
商家綁定
→ 接收新評論事件
→ 發送通知
→ 進入評論列表
→ 更新處理狀態
→ 參考回覆建議
→ 完成回覆
→ 記錄追蹤
→ 導流到其他生態圈節點（必要時）
```

## 10. 狀態流
| 狀態 | 說明 |
|---|---|
| new | 新評論，尚未查看 |
| read | 已查看 |
| pending_reply | 待回覆 |
| replied | 已回覆 |
| ignored | 不處理或暫不處理 |

## 11. 通知規則

### MVP 通知規則
1. 新評論建立時發送通知
2. 低星評論可標示為高優先級
3. 同一評論避免重複通知
4. 若通知失敗需記錄狀態

### 通知內容至少包含
- 商家名稱
- 星等
- 評論摘要
- 時間
- 進入後台查看的連結

## 12. 後台需求

### 商家端/管理端可見內容
- 評論列表
- 星等
- 評論文字
- 狀態
- 優先級
- 建議回覆內容
- 通知時間
- 處理紀錄

### 可執行操作
- 標記已讀
- 標記待回覆
- 標記已回覆
- 忽略評論
- 編輯回覆建議
- 依狀態/星等篩選

| 商家資訊不足 | Kairos.Site | 補足商家主頁與品牌入口 |
| 預約承接不足 | MyCal | 建立預約與後續轉換流程 |
| 曝光不足 | BizMap | 補名錄聚合與地區曝光 |
| 分享入口不足 | 秒傳名片 | 補電子名片與聯絡入口 |

## 16. 產品邊界
QuickNotifys 不以取代完整客服系統為目標，也不在首版承諾完全自動化回覆，而是先把評論通知、處理、追蹤與導流機制建立起來。

## 17. 一句話總結
**QuickNotifys 是 Kairos Engine 生態圈中的評論自動化節點，讓店家從被動看評論，進入主動管理評論、追蹤互動與串接轉換的流程。**
