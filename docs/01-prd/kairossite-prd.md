## 2. 產品定位
Kairos.Site 是 Kairos Engine 生態圈的核心主站，也是主要商家資料入口。其任務不是單純製作最精美的官網，而是協助中小企業、在地店家、個人工作室與行銷代管方，快速建立可被搜尋、可被分享、可被導流、可被後續診斷與補強的一頁式商家頁。

Kairos.Site 在生態圈中承擔「品牌入口、資料來源、導流起點」三項角色。其他節點原則上不重複維護完整主資料，而是使用 Kairos.Site 產生或維護的商家資料，進行曝光、診斷、評論管理、預約承接、電子名片分享或內部顧問流程。

### 一句話定位
Kairos.Site 是 Kairos Engine 的核心主站，負責讓商家建立第一個可被管理、可被導流、可被持續補強的數位據點。

## 3. 生態圈角色
依 Kairos Engine 生態圈總 PRD，Kairos.Site 是全生態圈的核心平台，需支援以下生態圈任務：

| 任務 | 說明 |
|---|---|
| 主資料入口 | 建立並維護商家名稱、類別、地區、介紹、圖片與主要連結 |
| 建頁入口 | 提供商家快速建立一頁式頁面的能力 |
| 導流起點 | 導向 AEO Scanner、BizMap、QuickNotifys、MyCal、秒傳名片與 K-Core |
| 補強依據 | 讓 K-Core、AEO Scanner 與顧問流程可依商家頁現況做診斷 |
| 治理節點 | 具備後台管理、下架、刪除與不適內容處理能力 |

## 6. 核心使用情境
1. 商家首次進入 Kairos 生態圈，透過 Kairos.Site 建立一頁式商家頁。
2. 商家已有 Google 商家檔案，但缺少品牌敘事、產品圖片與可承接流量的主頁。
3. 商家完成頁面後，前往 AEO Scanner 檢查 AI 可見度與可被理解程度。
4. 商家頁資料可被 BizMap 收錄，形成地區與分類曝光。
5. 商家若需要評論通知與回覆流程，可導入 QuickNotifys。
6. 商家若需要預約、付款或服務承接，可導入 MyCal。
7. 商家若需要快速分享聯絡入口，可串接秒傳名片。
8. 內部顧問若需健檢、報告與報價，可從 Kairos.Site 導入 K-Core。

## 8. 使用者頁面規格
### 8.1 頁面數量
Kairos.Site v1 採用「1 使用者 1 頁面」原則。每個使用者帳號原則上只對應一個主要商家頁，避免資料分散、重複收錄與治理困難。

### 8.2 頁面內容
商家頁至少應支援以下內容：

| 欄位 | 說明 |
|---|---|
| business_id | 商家唯一識別碼 |
| 商家名稱 | 對外顯示名稱 |
| 類別 | 商家主要分類 |
| 地區 | 城市、行政區或服務範圍 |
| 商家介紹 | 商家品牌、服務或產品描述 |
| 聯絡方式 | 電話、LINE、Email 或其他聯絡方式 |
| 主頁連結 | Kairos.Site 商家頁連結 |
| 預約連結 | 可串接 MyCal |
| 名片連結 | 可串接秒傳名片 |
| 模組啟用狀態 | AEO、BizMap、QuickNotifys、MyCal、K-Core 等狀態 |

### 8.3 頁面治理狀態
| 狀態 | 說明 |
|---|---|
| draft | 尚未發布 |
| published | 已發布 |
| hidden | 使用者或管理員暫時隱藏 |
| suspended | 因違規或審核需求暫停顯示 |
| deleted | 已刪除或不可恢復 |

## 9. 圖片與媒體規格
Kairos.Site v1 明確限制每個商家頁的圖片數量，以確保頁面品質、載入速度、儲存成本與治理效率。

### 9.1 圖片數量
| 類型 | 數量 | 用途 |
|---|---:|---|
| 封面圖片 | 1 張 | 作為商家頁主要視覺與分享預覽 |
| 產品 / 服務圖片 | 最多 5 張 | 展示主要商品、服務、空間或作品 |

### 9.2 圖片處理規則
1. 使用者上傳圖片後，系統需自動轉換為 WebP。
2. 圖片需經 Cloudflare 圖像層投放，以支援壓縮、尺寸變體與 CDN 快取。
3. 圖片需保留與商家頁、business_id、圖片用途的對應關係。
4. 不適圖片需可由後台刪除或使其失效。
5. 圖片顯示需兼顧行動裝置載入速度與基本視覺品質。

## 10. Cloudflare 圖像層
Cloudflare 圖像層是 Kairos.Site 圖片投放與最佳化的基礎設施。其目的在於降低前端載入成本、提升行動端體驗，並讓圖片治理具備可控性。

### 10.1 需求
| 需求 | 說明 |
|---|---|
| WebP 投放 | 所有正式顯示圖片應以 WebP 或瀏覽器支援的最佳格式投放 |
| 尺寸變體 | 依封面、縮圖、內容圖等用途產生合適尺寸 |
| CDN 快取 | 圖片需透過 Cloudflare 邊緣節點快取 |
| 圖片失效 | 後台刪除或下架圖片後，前台不得再持續展示 |
| 權限控管 | 非公開或下架頁面不得繼續暴露不適圖片 |

## 11. 後台管理與內容治理
Kairos.Site 必須具備後台管理能力，讓內部管理員能維護平台品質，避免惡意註冊、不實內容或違規內容破壞生態圈信任。

### 11.1 後台必要能力
| 功能 | 說明 |
|---|---|
| 商家頁列表 | 查看所有商家頁與狀態 |
| 商家頁檢視 | 查看商家資料、圖片、連結與模組啟用狀態 |
| 編輯資料 | 修正錯誤或不完整資訊 |
| 刪除頁面 | 移除不應保留的商家頁 |
| 下架頁面 | 暫停公開顯示，但保留內部紀錄 |
| 圖片管理 | 刪除或下架不適圖片 |
| 違規標記 | 標記詐騙、侵權、色情、仇恨、冒名或垃圾內容 |
| 操作紀錄 | 保留管理員操作紀錄，利於追蹤與稽核 |

### 11.2 不適內容範圍
不適內容包含但不限於：詐騙、冒名、侵權、色情、仇恨言論、非法服務、惡意跳轉、垃圾資訊、惡意註冊、明顯不實商家資料或其他違反平台政策之內容。

## 12. 隱私權政策與免責聲明
Kairos.Site 主站必須提供清楚可存取的隱私權政策與免責聲明。

### 12.1 隱私權政策
隱私權政策需說明：
1. 平台蒐集哪些商家與使用者資料。
2. 資料用途包含建頁、曝光、導流、治理、客服與生態圈模組串接。
3. 資料可能與 Kairos Engine 生態圈節點進行必要同步或狀態映射。
4. 使用者可如何提出資料更正、下架或刪除請求。

### 12.2 免責聲明
免責聲明需說明：
1. 商家頁內容由使用者或商家提供，平台不保證其完整性與即時正確性。
2. 平台可基於法令、平台政策或安全考量下架、刪除或限制內容。
3. 外部連結、預約、評論與第三方服務之結果由各服務提供方或商家自行負責。
4. AEO Scanner、K-Core 或其他診斷結果為輔助建議，不構成保證排名、流量或營收之承諾。

## 13. 資料邏輯
Kairos.Site 作為主要商家資料入口，需維持資料一致性，並為其他模組提供可識別、可導流、可映射的商家資料。

### 13.1 核心資料欄位
| 欄位 | 說明 |
|---|---|
| business_id | 生態圈共用商家識別碼 |
| user_id | 使用者識別碼 |
| business_name | 商家名稱 |
| category | 類別 |
| region | 地區 |
| site_url | Kairos.Site 商家頁 |
| cover_image_url | 封面圖片 |
| gallery_image_urls | 最多 5 張產品或服務圖片 |
| booking_url | MyCal 或其他預約連結 |
| card_url | 秒傳名片連結 |
| bizmap_status | BizMap 收錄狀態 |
| aeo_status | AEO Scanner 掃描狀態 |
| quicknotifys_status | QuickNotifys 啟用狀態 |
| k_core_case_status | K-Core 健檢案件狀態 |
| page_status | 商家頁狀態 |
| created_at / updated_at | 建立與更新時間 |

### 13.2 資料同步原則
1. Kairos.Site 為商家主資料來源。
2. BizMap、AEO Scanner、QuickNotifys、MyCal、秒傳名片與 K-Core 可使用 business_id 進行狀態映射。
3. 其他節點不應各自維護完整且互相衝突的商家主資料。
4. 若商家頁下架，相關導流節點需避免繼續導向不可用頁面。
5. 若商家頁刪除，需保留必要內部稽核資料，但前台不得公開展示。

## 14. 生態圈導流規則
Kairos.Site 必須依生態圈串連與導流架構，提供清楚的跨模組入口。

| 當前情境 | 導向節點 | 目的 |
|---|---|---|
| 商家剛建立頁面 | AEO Scanner | 檢查 AI 可見度與可被理解程度 |
| 商家需要更多曝光 | BizMap | 進入地區與分類名錄聚合 |
| 商家評論處理不足 | QuickNotifys | 建立評論通知、追蹤與回覆流程 |
| 商家需要預約承接 | MyCal | 建立預約、付款或服務承接流程 |
| 商家需要快速分享 | 秒傳名片 | 提供 LINE 電子名片與快速聯絡入口 |
| 商家需要診斷與報價 | K-Core | 建立內部健檢案件、報告與補強清單 |

## 15. 與關聯模組的關係
### 15.1 AEO Scanner
AEO Scanner 是附屬於 Kairos.Site 的 AEO 掃描工具，不作為獨立產品主站。Kairos.Site 應導引用戶在建頁後進行 AEO 掃描，檢查頁面內容、結構化資料、可讀性與 AI 可見度，並將掃描結果作為後續補強或導入 K-Core 的依據。

### 15.2 BizMap
BizMap 是 Kairos Engine 的商家名錄聚合層，負責地區、分類與列表型曝光。Kairos.Site 已發布商家頁可成為 BizMap 收錄來源；BizMap 不重做建頁，而是將曝光流量導回 Kairos.Site 商家頁、MyCal 或秒傳名片。

### 15.3 QuickNotifys
QuickNotifys 是評論自動化與口碑互動節點。Kairos.Site 提供商家主頁與商家資料基礎；當商家需要 Google 商家檔案評論通知、狀態追蹤與回覆流程時，可從 Kairos.Site 導入 QuickNotifys。

### 15.4 MyCal
MyCal 是預約與付款承接系統，負責將商家頁或名錄曝光後的流量轉化為實際預約、付款或服務請求。Kairos.Site 商家頁需可放置 MyCal 預約連結，並在適當位置引導使用者完成預約。

### 15.5 秒傳名片
秒傳名片是 LINE 電子名片與快速分享入口。Kairos.Site 可作為電子名片的品牌主頁連結，秒傳名片亦可回流至 Kairos.Site、MyCal 或社群聯絡入口，形成最短分享路徑。

### 15.6 K-Core
K-Core 是 Kairos Engine 的內部診斷核心，預計附掛於 BizMap 之下。Kairos.Site 商家頁提供 K-Core 健檢所需的商家基本資料、頁面狀態、圖片、連結與模組啟用狀態。內部顧問可依 Kairos.Site 現況建立 K-Core 健檢案件，產出報告、補強清單與初步報價，並將需求映射到 BizMap、QuickNotifys、MyCal、秒傳名片或 KairosLink。

## 17. MVP 與持續改版
### 17.1 v1 必做
1. Kairos.Site 作為核心主站與主資料入口。

3. 每頁支援 1 張封面與最多 5 張產品或服務圖片。

6. 強化後台審核、違規標記與操作紀錄。
